# XLSX reader planning

## Confirmed
- XLSX stage 1 is implemented and locally validated (583 tests; project/package JIT and Native AOT checks). The user confirmed successful CI after commit 7b798b7; stage 1 is complete. Stage 2 is complete: local validation passes with 688 tests and project/package JIT and Native AOT checks; the user confirmed CI passed after commit 32ff4d2. Stage 3 is authorized and implemented, with 719 local tests and project/package JIT and Native AOT checks passing; hosted CI is pending. The full approved behavior below spans all three stages. See xlsx-plan.md and ../xlsx.md for current scope.
- Retain the project requirements: .NET 10+, BCL-only runtime, Native AOT, no runtime reflection, and minimized allocations.
- Entry point: TabularFile.Xlsx<T>(), using existing generated mapping and annotations.
- Select the first worksheet by default; WithWorksheet(name) selects one by name.
- Reuse shared source lifetime, schema binding, queries, and materialization where applicable. Isolate XLSX parsing under Formats/Xlsx.

## Additional confirmed decisions
- Headers: first non-empty row by default; WithHeaderRow(number) selects a physical one-based row. Content and empty rules are defined below.
- Formulas: read saved cached results, do not calculate formulas, and throw when a formula has no cached result. Cached results may be stale.
- Initial scope: .xlsx only; defer .xls, .xlsb, and encrypted workbooks, with clear rejection errors.

## Worksheet selection and sparse rows: confirmed
- Worksheet names: match with StringComparer.OrdinalIgnoreCase; throw when a requested worksheet is missing. Do not fall back to another sheet.
- Hidden sheets: the default is the first worksheet in workbook order, including hidden or very-hidden worksheets. Named selection also permits hidden worksheets.
- Sparse data rows: use cell coordinates to keep columns aligned; omitted cells within the header range are empty values, with existing string/nullable/non-nullable conversion rules. Header-range policies below govern trailing cells.

## Header range and blank rows: confirmed
- Header range: column A through the last header cell with a non-empty resolved value. Reject empty/whitespace-only names or gaps within that range, using existing header validation and comparison rules. Ignore trailing cells containing formatting only. Whitespace is content when selecting the header row; it subsequently fails header validation if it is the whole name.
- Data beyond the header range: throw for any non-empty value or formula beyond the last header column. Ignore trailing empty or formatting-only cells. Formula presence counts as content even when its cached result is an empty string; existing missing-cache errors still apply.
- Blank rows: skip rows containing no non-empty values and no formulas within the read table, including physically omitted rows. Empty strings and formatting-only cells do not make a row non-blank; whitespace does. An explicitly selected header row must contain valid headers; do not search onward if it is blank. Header row numbers are physical, one-based worksheet row numbers.

## Merges, text, and errors: confirmed
- Merged cells: reject merged ranges intersecting the table's header or data rows/columns. Do not repeat the top-left value into other cells. Merged titles entirely above the selected header are permitted. The merge preflight section defines extent and timing.
- Text cells: support shared strings and inline strings; concatenate rich-text runs in document order, ignoring visual formatting and phonetic annotations. Preserve whitespace by default and reuse explicit field/header trimming options. Text escape behavior is specified below.
- Spreadsheet error cells: throw when encountered in the header or table data, including unmapped columns. Include worksheet/cell coordinates; omit raw values by default. Do not map errors such as #N/A to strings or nulls. Non-selected worksheets are not scanned for cell errors.

## Numeric, boolean, and string conversion: confirmed
- Numeric cells: parse stored numeric values with invariant rules, independent of WithCulture and visual number formatting. Convert directly to the requested numeric type without routing all values through double. Integer targets accept decimal/exponent notation only when the exact value is integral and in range; never round or truncate. Reject overflow and non-finite results.
- Boolean cells: native XLSX boolean cells map to bool/bool? using their stored 0/1 representation; do not reinterpret ordinary numeric 0/1 cells as booleans. Text cells mapped to bool retain the existing true/false conversion rules.
- Text-to-type and string targets: text cells use existing configured-culture conversion rules. For string targets, return resolved text, numeric storage text, or canonical true/false for native boolean cells, without display-format rendering. Date strings are specified below.

## DateTime and offset conversion: confirmed
- Numeric date conversion is target-type driven: a numeric cell mapped to DateTime is interpreted as an Excel serial using the workbook's 1900/1904 date-system setting, without requiring a date display style. Return DateTimeKind.Unspecified; never infer the local time zone. Ordinary numeric targets continue to receive the numeric value regardless of style.
- Invalid serial dates: throw for negative date serials, values outside the supported DateTime range, and the fictitious 1900-system leap day (serials >= 60 and < 61). Do not silently substitute a neighboring date. Serial zero and tick precision are specified below.
- DateTimeOffset: reject serial dates because they contain no explicit offset. Retain the existing requirement for an explicit offset in text values; apply the same offset-preserving/rejecting policies to native ISO date cells as specified below.

## DateOnly, TimeOnly, and TimeSpan: confirmed
- DateOnly: interpret numeric cells as workbook serial dates under the same calendar/range rules as DateTime, but require an exact whole-day value. Throw for any fractional-day component instead of discarding the time. Text cells retain existing configured-culture DateOnly parsing.
- TimeOnly: interpret numeric cells as a fraction of one day, requiring 0 <= value < 1. Reject negative values and values containing whole days rather than wrapping. Text cells retain existing configured-culture TimeOnly parsing. Tick rounding and boundary behavior are specified below.
- TimeSpan: interpret numeric cells as elapsed days, allowing fractional, negative, and multi-day values within the TimeSpan range. Do not apply the workbook calendar, leap-day rejection, or a 24-hour wrap to durations. Text cells retain existing configured-culture TimeSpan parsing. Tick precision is specified below.

## Serial zero, precision, and date strings: confirmed
- Serial zero: for DateTime/DateOnly, define 1900-system zero as 1899-12-31 and 1904-system zero as 1904-01-01. Fractions on day zero are permitted for DateTime, subject to the existing fractional-day rejection for DateOnly. Keep negative calendar serials invalid and reject the fictitious 1900-system day 60.
- Numeric temporal precision: convert stored day values directly to 100-nanosecond ticks using exact decimal/rational arithmetic, rounding only once to the nearest tick with midpoint-to-even. Validate original serial/calendar constraints before rounding, then validate the rounded result. Reject overflow, TimeOnly rounding to 24:00, or DateTime rounding onto the fictitious leap day; never wrap, clamp, or substitute. DateOnly fractional-day rejection occurs before rounding. This is temporal precision rounding, not permission to round numeric-to-integer conversions.
- Date strings: string properties keep the stored numeric text for serial-date cells, regardless of style. For native ISO date cells, return their stored ISO text. Do not render localized display formats or convert strings through a date type. Apply explicitly configured trimming consistently.

## Sources and storage: confirmed
- Sources and queries: offer paths, supplied streams, sync factories, and async factories for XLSX with existing ownership, single-use, cancellation, sync/async query, and materializer contracts. Async-only factories have a distinct XlsxAsync<T> entry point.
- Non-seekable input: copy to a temporary seekable file incrementally before opening the archive, rather than letting ZipArchive buffer the entire workbook in memory. Document startup cost and temporary-storage requirements; provide configurable storage location and a clear failure when storage is unavailable. Dispose/delete owned temporary files on completion, early exit, failure, and cancellation. Limits and no-temp policy are specified below.
- Shared-string storage: use a bounded in-memory cache with disk-backed storage/indexing when the configured memory budget is exceeded. Do not retain all unique strings or a growing offset array in RAM. Expose memory-budget/temp-storage configuration; tune defaults through measurements. Account separately for ZIP directory metadata, active record buffers, and other workbook metadata; do not claim constant total memory regardless of workbook structure.

## Temporary-file policy, limits, and async: confirmed
- Temporary-file policy: permit temporary files by default, created only when required, with an explicit option to forbid them. With temporary files disabled, reject non-seekable sources and throw if shared-string storage would exceed the configured memory budget. Do not silently fall back to unbounded RAM. Do not require access to a temporary directory when the selected query never needs temporary storage.
- Storage limits: expose optional limits for compressed workbook bytes, total decompressed bytes actually processed (including repeated reads/prepasses), individual resolved cell text, and aggregate temporary-file bytes. Null means unlimited, zero is valid, negatives fail immediately; exceeding a configured limit throws without truncation. Option names, counting rules, and the memory default are specified below.
- Async execution: use BCL async archive/file/XML operations where available, with no Task.Run wrapper or sync-over-async. Check cancellation during input copying, shared-string preprocessing, worksheet prepasses, buffered row processing, and reads/writes. Keep CPU parsing synchronous between awaits; cleanup all library-owned streams and temporary files on cancellation or early exit. Implementation must verify .NET 10 ZIP APIs and any unavoidable metadata/seek operations, documenting them accurately rather than claiming every operation is asynchronous.

## Native ISO dates, conversion boundaries, and worksheet scope: confirmed
- Native ISO date cells: support calendar dates YYYY-MM-DD and full date-times YYYY-MM-DDTHH:mm:ss with optional fractional seconds and optional Z or ±HH:mm offsets. Parse invariantly and validate actual dates. DateTime accepts only offset-free date/date-time values and retains Unspecified kind; DateTimeOffset requires a full date-time with explicit offset and preserves it. DateOnly accepts only the date-only form. TimeOnly/TimeSpan reject native full date cells instead of dropping date components. ISO precision and boundary rules are specified below.
- Cross-type conversions: native booleans map only to bool/bool? or string; numeric cells map only to numeric targets, the agreed serial-date/time/duration targets, or string. Native ISO dates map only to the agreed temporal targets or string. Other combinations throw. Text cells continue using existing supported conversions, including enum names, Guid, and char. Nullable forms retain the same type rules. Formula cached results follow their cached cell type.
- Workbook presentation/features: do not apply styles/number formats, hidden-row/column filtering, filters, or named-table boundaries; read the selected worksheet as the agreed header-based table, including hidden/filtered-out rows. Ignore comments, hyperlinks, drawings, charts, and external links; never fetch external data, calculate formulas, or execute macros. Macro-enabled .xlsm is outside the initial .xlsx scope and is rejected rather than processed. Both supported variants are specified below.

## Variants, structural validation, and diagnostics: confirmed
- XLSX variants: support both Transitional and Strict SpreadsheetML for the agreed feature subset, with explicit namespace/relationship handling and tests for both. Identify the workbook from package content types and relationships rather than trusting the filename extension. This does not imply full OOXML feature support or schema validation of ignored parts.
- Structural validation: throw for missing required workbook/worksheet parts, ambiguous duplicate ZIP parts/relationships/sheet names, invalid shared-string references, and malformed or inconsistent row/cell coordinates. Permit omitted row/cell coordinates only when their positions can be inferred unambiguously. Reject duplicate or decreasing row/cell positions instead of sorting or repairing. Validate consumed parts and required relationships; do not scan unrelated worksheets for cell errors.
- Diagnostics: retain the common exception family and expose worksheet name, physical one-based row/column, and A1 cell reference where available. Keep logical record numbering separate from worksheet row numbers and XML line numbers. Include mapped header/member when available; omit raw cell values and formula text by default. I/O and cancellation retain standard exceptions. The exception API is specified below.

## Configuration, merge preflight, and ISO precision: confirmed
- Configuration shape: WithWorksheet(string name), WithHeaderRow(int oneBasedRowNumber), WithTemporaryDirectory(string path), WithTemporaryFiles(bool enabled = true), and WithSharedStringMemoryBudget(long bytes). Options are immutable. Reject empty/whitespace-only worksheet names but preserve meaningful name whitespace; reject row numbers outside the worksheet range, negative budgets, and empty temporary paths immediately. A zero shared-string budget is valid. Reuse WithCulture, WithHeaderComparison, WithFieldTrimming, and WithHeaderTrimming; do not expose CSV-only encoding/dialect options on XlsxSource.
- Merge validation timing and extent: pre-read the selected worksheet's merge declarations before yielding records, then reopen its XML for streaming. Reject merges overlapping columns A through the final header column and rows from the header onward. This conservative table extent includes blank/trailing rows. Ignore merges wholly above the header or outside its columns. Do not validate or materialize future row values in this prepass. Document startup I/O and charge all repeated decompression against the configured limit.
- ISO precision: allow arbitrary non-empty fractional-second digit sequences subject to configured cell-text limits; round once to ticks using midpoint-to-even. Reject leap seconds, 24:00, invalid dates, invalid offsets, and rounding beyond the destination range. Never infer a local offset. Numeric and ISO temporal conversions share tick-rounding policy, while preserving their distinct lexical/calendar rules.

## Resource limits, memory default, and package handling: confirmed
- Resource option names: WithMaxWorkbookBytes(long?), WithMaxDecompressedBytes(long?), WithMaxCellTextLength(int?), and WithMaxTemporaryBytes(long?). Limits default to null (unlimited); zero is valid and negative values throw immediately. Decompressed bytes count every consumed part read, including prepasses/reopens. Cell text length counts resolved UTF-16 code units after XML/spreadsheet escape decoding and rich-text flattening, before trimming; apply to headers and unmapped cells too. Temporary bytes count aggregate live logical file lengths, including workbook spool, shared-string data, and disk index, not cumulative writes or filesystem block allocation.
- Memory default: use a provisional shared-string memory budget of 8 MiB, configurable down to zero. Account for retained text and in-memory index/cache storage rather than compressed XML size; fixed parser buffers and active cells are separate. Spill before exceeding the accounting budget, or throw when temporary files are forbidden. Permit tuning the default with benchmarks without another public-policy decision; do not claim a strict process-working-set cap.
- XML/package handling: prohibit DTDs and external XML resolution; reject external relationships required to locate the workbook, selected sheet, or shared strings. Ignore unrelated optional extension content only when it does not replace required data or declare unsupported must-understand semantics. Throw for unsupported required markup instead of guessing. No archive entries are extracted by their package paths; generated temporary files use library-chosen names under the configured temporary directory.

## Empty cells, headers, and stream origin: confirmed
- Empty/content rules: non-formula cells without a stored value or inline text are blank, including style-only cells; present empty text is also empty. A present non-empty shared-string index must resolve successfully even when the resolved string is empty. Non-empty malformed typed values throw, not become blank. Native false and numeric zero count as content. Formula presence always counts as content; an empty cached string is valid, but missing cached values or empty numeric/boolean/date caches throw. Row/header selection tests content before optional trimming. These rules also apply to unmapped cells.
- Header conversion: use each cell's agreed string representation, including resolved strings, stored numeric/ISO text, and canonical true/false. Formula headers use cached results under the same rules as other cells. Select the first row with content (including formulas) when no header row is specified; if its resolved header names are invalid, throw instead of searching for another row. A selected sheet with no valid header throws. Valid header-only sheets produce an empty sequence after schema validation.
- Stream origin: treat the supplied stream's current position as the workbook origin and the remaining stream through its end as the archive. For seekable sources, use a relative view so archive seeks never move before that origin; do not rewind to absolute zero. Do not promise to restore the caller's original position. Non-seekable input copies from its current position to the temporary archive. Retain existing claim/disposal behavior.

## Text escapes, execution timing, and exception API: confirmed
- Spreadsheet text escapes: decode _xHHHH_ sequences once, preserving escaped literal sequences such as _x005F_x0041_ as literal _x0041_. Apply to shared/inline/cached string values, before trimming or header matching, and enforce resolved-text limits afterward. Preserve malformed lookalike sequences as literal text rather than guessing; XML syntax/encoding errors still throw. Decode text runs independently before concatenating them, so runs cannot accidentally create a new escape sequence. Preserve decoded UTF-16 code units rather than performing Unicode normalization.
- Deferred execution/errors: configuration validates arguments immediately but does not open sources. Start archive/schema/merge/shared-string setup on the first move; surface failures there. Do not pre-convert later data rows. Data conversion failures occur when enumeration reaches the row; preprocessing may detect structural/metadata failures earlier. Take/early exit need not validate unread data rows, but always disposes owned streams/temp files.
- Exception API: add XlsxFormatException derived from TabularFileException for workbook/format failures, while reusing TabularSchemaException and TabularConversionException. Add nullable WorksheetName, WorksheetRowNumber, CellReference, and PartName properties to the common base; leave these null for CSV. Existing ColumnIndex is a one-based worksheet column for XLSX. Keep RecordNumber logical (header = 1); use 0 when unknown before record context. Existing LineNumber/FailureLineNumber retain text-file meanings and are 0 for XLSX when unavailable; do not overload them with worksheet rows. Exception messages/inner exceptions must not leak raw values or formulas. I/O and cancellation retain standard types.
